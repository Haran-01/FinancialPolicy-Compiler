# Developer Guide — FinPolicy Compiler

This guide covers day-to-day development tasks for contributors.

---

## Architecture Overview

```
┌────────────┐     HTTP/REST      ┌────────────────┐
│  Frontend  │ ◄────────────────► │    Backend     │
│ React + TS │                    │  Hono + Prisma │
└────────────┘                    └────────┬───────┘
                                           │
                                  ┌────────▼───────┐
                                  │   PostgreSQL   │
                                  └────────────────┘
                                           │
                                  ┌────────▼───────┐
                                  │   @finpolicy/  │
                                  │   compiler     │
                                  └────────┬───────┘
                                           │
                         ┌─────────────────▼──────────────────┐
                         │  Lexer → Parser → AST → Semantic   │
                         │  → IR → Optimizer → CodeGen        │
                         └────────────────────────────────────┘
```

The backend calls the compiler package synchronously (Phase 3) or via a worker thread (Phase 4+).

## How to Add a New API Endpoint

1. **Define the DTO** in `shared/src/types/` (if input/output types are shared with frontend).

2. **Create the route handler** in `backend/src/routes/<resource>/`:
   ```typescript
   // backend/src/routes/policies/get-policy.ts
   import type { Context } from 'hono'
   export async function getPolicy(c: Context): Promise<Response> {
     const id = c.req.param('id')
     // ... service call
     return c.json({ success: true, data: policy })
   }
   ```

3. **Register the route** in `backend/src/routes/<resource>/index.ts`:
   ```typescript
   router.get('/:id', requireAuth, getPolicy)
   ```

4. **Write an integration test** in `backend/src/routes/<resource>/<name>.test.ts`.

5. **Document the endpoint** in [`docs/API_REFERENCE.md`](API_REFERENCE.md).

---

## How to Add a New Frontend Page

1. Create the page component in `frontend/src/pages/<PageName>/<PageName>.tsx`.
2. Add a route entry in `frontend/src/router/index.tsx`.
3. Add navigation in `frontend/src/components/Sidebar.tsx` if needed.
4. Export from `frontend/src/pages/index.ts`.

---

## How to Add a Compiler Phase Stub

1. Create the interface file: `compiler/src/<phase>/<phase>.interface.ts`
2. Export all types from `compiler/src/index.ts`
3. Add a stub test in `tests/compiler/<phase>.stub.test.ts`
4. Update the [`FOLDER_STRUCTURE.md`](FOLDER_STRUCTURE.md)

## How to Run Tests

```bash
# All workspaces
npm run test

# Backend only
npm test --workspace=backend

# Frontend only
npm test --workspace=frontend

# Root-level compiler stubs
cd tests && npx vitest run

# With coverage
npm test --workspace=backend -- --coverage
```

## Database Commands

```bash
# Create a new migration after editing schema.prisma
npm run db:migrate         # (runs prisma migrate dev)

# Regenerate the Prisma client after schema change
npm run db:generate        # (runs prisma generate)

# Seed default users
npm run db:seed            # (runs ts-node database/seeds/admin.seed.ts)

# Open Prisma Studio (DB browser)
cd backend && npx prisma studio

# Reset database (drops all data, re-runs migrations + seed)
cd backend && npx prisma migrate reset
```

## Environment Setup

| Variable              | Description                           | Example                            |
|-----------------------|---------------------------------------|-------------------------------------|
| `DATABASE_URL`        | PostgreSQL connection string          | `postgresql://user:pass@localhost/db` |
| `JWT_ACCESS_SECRET`   | 64-byte hex JWT signing secret        | (generated by `generate-secret.js`) |
| `JWT_REFRESH_SECRET`  | 64-byte hex JWT signing secret        | (generated by `generate-secret.js`) |
| `JWT_ACCESS_EXPIRES_IN` | Access token TTL                   | `15m`                               |
| `JWT_REFRESH_EXPIRES_IN` | Refresh token TTL                 | `7d`                                |
| `PORT`                | Backend HTTP port                     | `3001`                              |
| `VITE_API_URL`        | Backend URL (frontend build time)     | `http://localhost:3001/api`         |

Generate JWT secrets:
```bash
node scripts/generate-secret.js
```

## Coding Conventions

- Strict TypeScript — no `any`, no `@ts-ignore` without a comment explaining why.
- All API handlers return `ApiResponse<T>` from `@finpolicy/shared`.
- Use `import type` for type-only imports.
- 2-space indentation, single quotes, trailing commas (enforced by Prettier).
- All exports from a module are explicitly listed (no `export * from`).
